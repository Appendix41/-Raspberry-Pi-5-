# 树莓派控制宇树 GO-M8010-6 电机

基础部分按 [FlowUs 息流原教程](https://flowus.cn/share/7200c2d7-e0b9-410e-b312-23d16169213b) 的操作顺序整理：配置环境 → 获取 SDK → 编译 → 运行。最后增加一个自定义正反转程序，说明如何自己编写控制逻辑。

本文使用 C++ 和树莓派终端。`bash` 代码块输入终端；`cpp` 和 `cmake` 代码块写入指定文件，不要输入终端。

## 实验准备

需要：树莓派及其独立电源、GO-M8010-6 电机、配套高速 USB 转 RS485 模块（支持 4 Mbps）、转接板和连接线、电机用 24V 直流电源。电源电流容量应按电机手册和实际负载选择，不在本文预设固定 A 数。

接线关系：树莓派 USB 连接 USB 转 RS485，再经配套转接板连接电机；24V 电源通过转接板给电机供电。按配套板和线缆标识接线，不用树莓派给电机供电。

> 先断电接线，确认电机固定、空载、转轴周围无人和杂物，再上电测试。不连接人体或外骨骼机构测试。电机电源开关应随手可断，不要带电插拔电机接头。软件退出不等于可靠急停。

本文按本次已跑通的环境编写：串口 `/dev/ttyUSB0`、电机 ID 为 `0`、SDK 位于 `~/unitree_actuator_sdk-main`。`~` 表示当前用户的主目录；本次账号为 `appendix41`，对应 `/home/appendix41`。

## 1. 配置 C/C++ 环境

打开树莓派终端，依次输入：

```bash
sudo apt update
sudo apt install build-essential
gcc --version
g++ --version
make --version
```

后三条能显示版本号，说明对应工具已安装。已配置好的树莓派不必每次重复安装。

## 2. 获取电机 SDK

打开 [宇树官方 SDK 仓库](https://github.com/unitreerobotics/unitree_actuator_sdk)，选择 **Code → Download ZIP**，把下载的压缩包解压到树莓派的主目录，使工程目录为：

`~/unitree_actuator_sdk-main`

如果已经有这个目录，直接使用现有 SDK，不要再套一层同名文件夹。

在终端进入工程根目录：

```bash
cd ~/unitree_actuator_sdk-main
ls
```

应能看到 `CMakeLists.txt`、`example`、`include`、`lib` 等内容。

SDK 已封装通信协议。后面运行程序时，程序会打开串口并通过 RS485 收发数据，不需要先手动发送十六进制指令。

## 3. 编译原例程

在工程根目录依次输入：

```bash
mkdir build
cd build/
cmake ..
make
```

如果工程根目录已经有 `build`，跳过 `mkdir build`，直接进入现有的 `build`。不要在 `build` 里面再新建一个 `build`。

`cmake ..` 读取上一级工程目录中的 `CMakeLists.txt`，生成构建文件；`make` 按构建规则编译程序。

编译结束后查看生成的文件：

```bash
ls
```

找到 `example_goM8010_6_motor`。它是本次要运行的 GO-M8010-6 电机例程；A1、B1 例程不是本次使用的型号。

> 环境补充：如果提示 `cmake: command not found`，先执行 `sudo apt install cmake`，再回到当前步骤。这是缺少工具时的补充，不是每次运行都要做的操作。

## 4. 运行原例程

保持终端当前位置在 `build` 文件夹。确认接线、供电和空载固定条件后输入：

```bash
sudo ./example_goM8010_6_motor
```

通信正常时，电机会按照原例程设定持续旋转。

这个命令只是启动已经编译好的程序。串口打开、控制指令发送和反馈接收，都是程序运行过程中自动完成的。

> 结束原例程时，不要只依赖 `Ctrl+C`：本次实测曾出现终端退出后电机仍继续转动。对于这里的固定、空载测试，先切断电机 24V 电源，再按 `Ctrl+C` 结束终端程序。

## 5. 以后再次运行

没有修改源码时，不用重新安装、下载或编译。打开终端直接输入：

```bash
cd ~/unitree_actuator_sdk-main/build
sudo ./example_goM8010_6_motor
```

如果终端提示符已经显示 `~/unitree_actuator_sdk-main/build`，第一行 `cd` 可以省略。`./` 表示运行当前目录中的文件。

**到这里是息流教程的基础驱动流程。以下是本项目新增的拓展，不属于原教程步骤。**

## 6. 拓展：自己编写周期性正反转程序

目标：正转约 2 秒 → 停约 1 秒 → 反转约 2 秒 → 停约 1 秒，重复 3 轮后退出。输出端目标速度约为 90°/s，起停有约 0.3 秒的速度过渡。

这是速度控制练习，不是精确角度控制。运行时间还受通信耗时影响，不能据此保证每次恰好转过 180°。本次已在固定、空载的树莓派实验环境中跑通，不代表适合直接连接人体或带载机构。

### 6.1 新建 C++ 源文件

不用修改宇树原例程。本次把新文件放在 SDK 根目录，与 `CMakeLists.txt` 同级，完整路径为 `/home/appendix41/unitree_actuator_sdk-main/my_reverse.cpp`。

终端输入：

```bash
nano ~/unitree_actuator_sdk-main/my_reverse.cpp
```

在打开的编辑器里粘贴下面的**完整代码**。只复制代码内容，不复制代码块外的说明或反引号。若文件已存在且内容一致，不必重新创建或重复粘贴。

```cpp
// Fixed, unloaded bench test only; no precise angle positioning.
// Forward ~2 s, stop ~1 s, reverse ~2 s, stop ~1 s; repeat 3 times.
// Speed targets ramp over ~0.3 s. Software stop is not an emergency stop.
#include <unistd.h>
#include <algorithm>
#include <cmath>
#include <csignal>
#include <iostream>
#include <stdexcept>
#include "serialPort/SerialPort.h"
#include "unitreeMotor/unitreeMotor.h"
volatile std::sig_atomic_t running = 1;
void onSignal(int) { running = 0; }

int main() {
    std::signal(SIGINT, onSignal);
    std::signal(SIGTERM, onSignal);
    try {
        SerialPort serial("/dev/ttyUSB0");
        MotorCmd cmd;
        MotorData data;
        cmd.motorType = data.motorType = MotorType::GO_M8010_6;
        cmd.id = 0;
        cmd.mode = queryMotorMode(cmd.motorType, MotorMode::FOC);
        cmd.q = cmd.dq = cmd.tau = cmd.kp = 0.0f;
        cmd.kd = 0.02f;
        const float ratio = queryGearRatio(cmd.motorType);
        const float speed = 1.5708f; // Output rad/s: target about 90 degrees/s.
        auto exchange = [&]() {
            data.correct = false;
            if (!serial.sendRecv(&cmd, &data) || !data.correct || data.motor_id != cmd.id)
                throw std::runtime_error("No valid motor reply");
            if (data.merror != 0)
                throw std::runtime_error("Motor error " + std::to_string(data.merror));
        };
        int result = 0;
        try {
            exchange(); // Check communication with a zero-speed command first.
            if (!std::isfinite(ratio) || ratio <= 0.0f)
                throw std::runtime_error("Invalid gear ratio");
            for (int tick = 0; tick < 1800 && running; ++tick) {
                const int phase = (tick / 100) % 6;
                const float target = (phase < 2 ? speed : phase < 3 ? 0.0f :
                                      phase < 5 ? -speed : 0.0f) * ratio;
                const float step = 5.0f * ratio * 0.01f;
                cmd.dq += std::max(-step, std::min(step, target - cmd.dq));
                exchange();
                if (!std::isfinite(data.dq) || std::fabs(data.dq) > 2.0f * speed * ratio)
                    throw std::runtime_error("Unexpected speed: stop test");
                if (tick % 100 == 0)
                    std::cout << (target > 0 ? "Forward" : target < 0 ? "Reverse" : "Stop") << '\n';
                usleep(10000);
            }
        } catch (const std::exception& e) {
            std::cerr << "Test stopped: " << e.what() << '\n';
            result = 1;
        } catch (...) { std::cerr << "SDK error; stopping\n"; result = 1; }
        cmd.mode = queryMotorMode(cmd.motorType, MotorMode::BRAKE);
        cmd.q = cmd.dq = cmd.tau = cmd.kp = cmd.kd = 0.0f;
        bool stopped = false;
        for (int i = 0; i < 5; ++i) {
            try {
                data.correct = false;
                if (serial.sendRecv(&cmd, &data) && data.correct &&
                    data.motor_id == cmd.id && data.mode == cmd.mode) stopped = true;
            } catch (...) {}
            usleep(10000);
        }
        if (!stopped) { std::cerr << "STOP NOT CONFIRMED: switch off motor power.\n"; return 1; }
        std::cout << "Stop mode acknowledged; output position is not held.\n";
        return result;
    } catch (...) { std::cerr << "Cannot initialize SDK; keep motor power off.\n"; return 1; }
}
```

按 `Ctrl+O`，再按回车保存；按 `Ctrl+X` 退出。打开编辑器时给出的文件路径就是保存路径，不需要另外命名。开头三行 `//` 是注释，不会作为控制指令执行。

### 6.2 把新文件加入编译清单

终端输入：

```bash
nano ~/unitree_actuator_sdk-main/CMakeLists.txt
```

保留原有内容，在末尾追加下面两行。如果已经有 `my_reverse` 对应的两行，就检查或修改原条目，不要重复添加。

```cmake
add_executable(my_reverse my_reverse.cpp)
target_link_libraries(my_reverse ${EXTRA_LIBS})
```

第一行把根目录的 `my_reverse.cpp` 注册成名为 `my_reverse` 的可执行程序；第二行让它链接宇树 SDK 库。这里文件在根目录，所以不能写成 `example/my_reverse.cpp`。

按 `Ctrl+O` → 回车 → `Ctrl+X` 保存并退出。

### 6.3 编译新程序

终端输入：

```bash
cd ~/unitree_actuator_sdk-main/build
cmake ..
make my_reverse
```

出现 `Built target my_reverse`，且没有编译错误，再运行下一步。`make my_reverse` 只构建这个目标及其依赖；直接使用 `make` 也可以，会构建默认目标中需要更新的部分。

### 6.4 运行新程序

先结束原来的电机程序，不要让两个程序同时占用同一个串口。确认电机固定、空载，电源开关可随时切断。在当前 `build` 目录输入：

```bash
sudo ./my_reverse
```

终端会显示 `Forward`、`Stop`、`Reverse` 等阶段提示。正常完成 3 轮后，程序会发送停止模式，并显示：

```text
Stop mode acknowledged; output position is not held.
```

它表示收到停止模式反馈，**不表示停在某个角度并保持位置**。

中途按 `Ctrl+C` 会请求程序退出并尝试发送停止指令。若电机继续转动、运动异常，或提示 `STOP NOT CONFIRMED`，立即切断电机 24V 电源，不要把软件退出当作硬件急停。

### 6.5 自己修改转速和循环次数

停止程序后，重新打开源码：

```bash
nano ~/unitree_actuator_sdk-main/my_reverse.cpp
```

**修改转速：**找到 `const float speed = 1.5708f;`。这里是输出端目标速度，单位为 rad/s；`1.5708` 约为 90°/s。第一次练习可以改小，例如改成 `0.7854f`，约为 45°/s。保持它为正数，正反方向已经由后面的阶段逻辑控制。

**修改循环次数：**找到 `tick < 1800`。在当前阶段安排不变时，每轮是 600 次循环；`600` 为 1 轮，`1200` 为 2 轮，`1800` 为 3 轮。

阶段由 `(tick / 100) % 6` 决定，每个阶段名义上约 1 秒：

| `phase` 的值 | 目标动作 |
| --- | --- |
| `0`、`1` | 正转，共约 2 秒 |
| `2` | 零速度目标，约 1 秒 |
| `3`、`4` | 反转，共约 2 秒 |
| `5` | 零速度目标，约 1 秒 |

零速度阶段包含减速过渡，不是从阶段开始就瞬间停住。实际时间还包含串口通信耗时。

保存退出后，只改了现有 `.cpp`、没有修改编译清单时，在终端执行：

```bash
cd ~/unitree_actuator_sdk-main/build
make my_reverse
sudo ./my_reverse
```

仅在编译成功后执行运行命令。改过源码必须重新编译，直接运行旧的可执行文件不会应用新修改。

### 6.6 以后怎样编写自己的控制程序

基本方法不变：新建 `.cpp` → 调用 SDK 并写自己的动作逻辑 → 在 `CMakeLists.txt` 注册一次 → 编译 → 运行。源码不一定放在 `example`；本例放在根目录，关键是编译清单里的路径与实际位置一致。

本例中，`SerialPort serial("/dev/ttyUSB0");` 打开串口，`serial.sendRecv(&cmd, &data);` 发送控制要求并接收反馈。给 `cmd` 赋值只是准备数据，调用收发函数才真正与电机通信。

需要了解 SDK 能设置什么时，查看 [官方接口头文件](https://github.com/unitreerobotics/unitree_actuator_sdk/blob/main/include/unitreeMotor/unitreeMotor.h) 和电机用户手册。常用字段如下：

| 字段 | 含义 |
| --- | --- |
| `cmd.id` | 要控制的电机 ID |
| `cmd.dq` | 转子端目标角速度，单位 rad/s；本例通过减速比把输出端速度换算后赋值 |
| `cmd.q` | 转子端目标位置，单位 rad |
| `cmd.tau` | 前馈力矩，不是电机最终总输出力矩 |
| `cmd.kp`、`cmd.kd` | 混合控制的位置、速度误差增益；本例 `kp = 0`，不进行位置跟踪 |
| `data.q`、`data.dq` | 位置、速度反馈，使用时要注意转子端与输出端换算 |
| `data.merror` | 电机反馈的错误码；具体含义以对应型号手册为准 |

这些是 C++ 程序里的接口字段，不是可以直接输入终端的命令。精确转过指定角度需要另外设计位置目标和到位判断，不能只修改本例的转动时间。初次练习先保留本例的增益、通信检查和停止逻辑。
