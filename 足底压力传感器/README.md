# 足底压力传感器

这一部分记录冠拓 18 点足底压力传感器在 Windows 和树莓派上的调试过程。当前重点是 Arduino Uno 中转方案；Windows 端用于确认传感器和 18 个点位本身是否正常。

## 一、文件和设备

```text
足底压力传感器/
├─ README.md
├─ 图片
└─ 代码/Arduino_Uno/
   ├─ pressure_original_9600.ino
   ├─pressure_uno_bridge_115200.ino
   └─setup.exe
```

设备关系：

| 设备 | 作用 |
| --- | --- |
| 18 点柔性鞋垫 | 感受脚底压力 |
| 采集模块 | 扫描 18 个点并通过串口输出 |
| Arduino Uno | 接收采集模块数据并通过 USB 输出 |
| Raspberry Pi | 运行 Arduino IDE、上传程序和查看串口 |

## 二、方案 1：Windows系统上下位机软件调试

### 1. 硬件连接
![硬件连接](./图片/333.png)

Windows 端使用 CH340/CH341 USB 转串口设备和厂家上位机。CH340 只是 USB 到串口的转换芯片，不是鞋垫本体，也不接树莓派 GPIO。
### 2. 操作调试

上位机软件安装：
点击./代码/Arduino_Uno/setup.exe，一直点击下一步安装即可
安装完成后，桌面生成文件M0406
![文件](./图片/wenjian.png)

操作顺序：
1. 将采集模块的 USB 供电线按模块标记接好：红线接 `+5V`，黑线接 `GND/-`。这根线只供电，不传输数据。
2. 将独立的 CH340/CH341 接收器插入 Windows 电脑。
3. 在设备管理器中确认出现 `USB-SERIAL CH340 (COMx)`。
4. 打开厂家 18 点足底压力上位机，选择实际 COM 口。
5. V2.0 模块优先选择 `115200`；如果你的模块被设置过 9600，要以实际调试结果为准。
![足底压力传感器上位机界面](./图片/222.png)

6. 依次点击打开串口，蓝牙扫描，发现蓝牙设备后点击蓝牙绑定，观察返回数据以及蓝牙设备号如果出现如图所示结果则证明绑定成功（蓝牙设备号是不同的，但是没有绑定成功此栏是空白）
![足底压力传感器上位机界面](./图片/111.png)
7. 按点位图逐个按压 1～18 号位置，确认界面对应位置发生变化。
![足底压力传感器上位机界面](./图片/444.png)
压力单位为`克`出现数据则证明传感器调试成功


## 三、方案 2：树莓派+arduino uno

拆卸蓝牙模块    
冠拓电子提供的采集模块一共有两个版本 1.串口版 2.蓝牙版，我们采用的是蓝牙版
根据冠拓电子官方说法，其提供的蓝牙版采集模块会影响串口的通讯。这里我做了个小实验，将蓝牙版背部的蓝牙模块进行了拆除，发现也是可行的，只是效果不如单独的串口版好
如图所示，利用热风枪将蓝牙模块拆除
![拆除](./图片/拆.png)

### 1. 硬件连接
Arduino 中转方案连接如下：

```text
压力鞋垫排线 → 采集模块
采集模块 VCC  → Uno 5V
采集模块 GND  → Uno GND
采集模块 TX   → Uno D0/RX（数字 0）
采集模块 RX   → 不接
Uno USB-B      → 树莓派 USB-A
树莓派 USB-C  → 独立电源
```
![硬件连接](./图片/555.png)
重要事项：

- 采集模块上的红黑 USB 供电线在这套接法中不要再接，避免重复供电；模块由 Uno 的 5V 供电。
- 树莓派和 Uno 之间只连接 USB，不需要接树莓派 GPIO。
- 不使用 Windows 的 CH340 接收器。
- Uno 的 D0/RX 是唯一硬件串口的接收端，上传时不能被采集模块 TX 占用。

### 2.代码调试


代码目录里保留了两个版本：

`pressure_original_9600.ino` 是资料中 Arduino 示例的原文件。它固定使用：

```cpp
SensorSerial.begin(9600);
DebugSerial.begin(9600);
```

因此模块、程序和串口监视器都必须是 9600。该版本保留用于对照原文，但没有完整检查帧头、长度和校验和。

`pressure_uno_bridge_115200.ino` 按 V2.0 的 39 字节协议读取，并检查帧头和校验和。它固定使用 115200，输出格式为：

```text
P,left,p1,p2,...,p18
P,right,p1,p2,...,p18
```

建议优先使用 Windows 端已经验证过的波特率。两个版本不要混用：模块如果是 115200，就不能直接上传原始 9600 版本后期待得到正确数据。

正确的烧录顺序

1. 关闭 Arduino 串口监视器和其他串口工具。
2. 断开采集模块 TX 与 Uno D0/RX 的连接；最好让采集模块断电。
3. 只把 Uno USB-B 接到树莓派。
4. 打开 Arduino IDE，选择 `Arduino Uno`。
5. 选择 `工具 → 端口` 中实际出现的 `/dev/ttyACM0`（也可能是其他端口）。
6. 打开对应 `.ino` 文件，点击“验证”。
7. 编译完成后点击“上传”，等待“上传成功”。
8. 拔掉 Uno USB，完全断电。
9. 接回 `采集模块 TX → Uno D0/RX`，采集模块 RX 仍不接。
10. 重新插入 Uno USB，等待几秒后再打开串口监视器。

如果上传出现 `not in sync` 或 `programmer is not responding`，第一项检查就是 TX 是否忘记断开。波特率不会造成 Arduino 引导程序的上传错误。


如果使用 115200 桥接程序：

1. 在 Arduino IDE 打开 `工具 → 串口监视器`。
2. 选择实际 Uno 端口和 `115200`。
3. 观察是否持续出现 `P,left,...` 或 `P,right,...`。
4. 按点位图依次按压 1～18 号区域，检查同一编号的数值是否上升。

如果使用原始程序，串口监视器选择 `9600`，输出形式类似：

```text
[1] value [2] value ... [18] value
```

## 七、问题排查

| 现象 | 处理 |
| --- | --- |
| `/dev/ttyACM0` 不出现 | 换 USB 数据线和 USB 口；确认 Uno 已上电 |
| 上传 `not in sync` | TX 从 D0/RX 拔掉，关闭串口监视器后重新上传 |
| 串口乱码 | 模块、代码和监视器波特率统一 |
| 串口完全没有数据 | 检查 VCC、GND、TX→RX 和模块供电 |
| 所有点为 0 | 先在 Windows 上位机确认采集模块和鞋垫是否正常 |
| 只有部分点为 0 | 记录具体编号，检查排线和点位；不要直接把无效点改成正常值 |
| 低电压提示 | 给树莓派使用稳定电源，避免 Uno/传感器反向给树莓派供电 |
